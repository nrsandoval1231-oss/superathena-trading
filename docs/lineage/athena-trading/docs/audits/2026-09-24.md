## Findings, in repair priority

### AT-01 — P1: Frozen input verification remains bypassable outside the repaired subsample index path

**Impact:** A run can consume data that does not match the frozen research inputs while retaining the frozen plan identity.

The full-run _assert_full_plan_receipts function checks supplied hash strings and selected metadata. It does not recompute either receipt's canonical hash or bind the input file bytes to the receipt. The repaired index verifier is called in the subsample branch, not the full-run branch.

The snapshot gap is broader: volume/gold subsample runs do not validate a snapshot receipt. They only require matching opportunity IDs and the expected feature keys. The snapshot loader does not validate bucket value types or decision-time provenance.

**Reproduction:** Created 16,705 synthetic TRAINING rows and matching synthetic snapshot rows; supplied minimal fabricated receipts containing the expected frozen hash strings. The receipt self-hash was invalid. The authorized full-run path reached the first injected Actor request, including a deliberately invalid future-return string in a feature. The probe stopped there; no provider was called.

**Repair:** Apply one canonical, byte-binding verifier to both opportunity and snapshot inputs on every evidence-producing run path. Check receipt digest, data digest, row count, assignment, provenance, feature domains, and partition. Bind the exact verified input identities into the run manifest. Keep fixture/smoke evidence explicitly separate.

### AT-02 — P1: Resume accepts modified inputs and edited decisions without detecting corruption

**Impact:** An altered or mixed run can be accepted as a completed in-sample run, undermining attribution and reproducibility.

_load_ledger checks sequence, authority, Actor identity, and partition. It does not verify record content hashes or a persisted integrity anchor. Resume skips completed keys without comparing saved request/packet hashes with the newly constructed request. The checkpoint is written but is not validated on resume. result_hash deliberately excludes records and does not include a digest of their contents.

**Reproductions:**

1. Completed a one-opportunity, seven-request fixture run.
2. Changed the macro snapshot while preserving opportunity IDs.
3. Resumed: zero new requests, old packet hash retained, status LOCAL_TRAINING_IN_SAMPLE. A fresh run over the changed input produced a different packet hash.
4. Edited the first saved decision from PASS to ENTER_HIGH_CONVICTION.
5. Resumed again: the edited decision was accepted with zero new requests, and result_hash was identical to the original run's hash.

**Repair:** Freeze a run manifest containing input, Actor, arm, prompt, and sample identities. Bind ordered ledger contents to that manifest and to a durable checkpoint. Before skipping a completed request, verify its expected identity and content integrity. Reject duplicate, unknown, or mismatched records. Include the ledger digest in the result hash. Preserve interruption recovery without silently accepting edited history.

Sources: [src/athena_trading/aat_v2/ollama_training.py:521](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/aat_v2/ollama_training.py#L521); [src/athena_trading/aat_v2/ollama_training.py:535](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/aat_v2/ollama_training.py#L535); [src/athena_trading/aat_v2/ollama_training.py:823](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/aat_v2/ollama_training.py#L823); [src/athena_trading/aat_v2/ollama_training.py:984](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/aat_v2/ollama_training.py#L984).

### AT-03 — P1 before broker use: Paper risk accounting can close a position that the broker never filled

**Impact:** Risk limits and reported realized results can diverge from broker exposure.

The walker registers an open position after an order acknowledgement, then closes its shadow using simulated run_position exits. It does not wait for confirmed broker fills or send the corresponding broker exit. The README discloses that stops, harvests, and flattening remain engine-side; the code demonstrates the resulting inconsistency.

**Reproduction:** Ran the shipped bar fixture with the standard FixtureBroker, which leaves orders NEW until explicitly filled. No fill was applied. At completion the risk ledger showed realized_r=-1.0 and one open position, while two broker orders were still NEW with filled_quantity=0 and no cancellations.

**Repair:** Keep simulation accounting separate from broker account state. Make fill confirmations, partial fills, rejects, cancellation acknowledgements, and exit fills drive the operational ledger. Implement protective stops, exit/flatten orders, daily reconciliation, and restart recovery before unattended paper use.

Sources: [src/athena_trading/paper/walk.py:194](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/paper/walk.py#L194); [src/athena_trading/paper/walk.py:215](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/paper/walk.py#L215); [src/athena_trading/paper/alpaca.py:123](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/paper/alpaca.py#L123); [src/athena_trading/paper/fixture.py](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/src/athena_trading/paper/fixture.py); [README.md](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/README.md).

### AT-04 — P1 before activating Astra Desk: Kill-switch flattening does not close positions, and a broker error prevents halting

**Impact:** The operator can see internal books flattened even though no position-close operation was sent. A broker failure can prevent the halt latch from being set.

Astra's AlpacaPaperBroker.flatten calls DELETE /v2/orders only. KillSwitch.trip calls flatten before setting _halted=True, then clears internal books. No position-close call or flat-position reconciliation is present in that method.

**Reproductions:** With an injected transport, trip sent only DELETE /v2/orders and returned halted=true. With a broker whose flatten raises an outage error, trip raised and the kill switch remained halted=false.

**Repair:** Persist the halt first so new sends are blocked even during a broker outage. Cancel pending orders, close open positions through explicit broker operations, then confirm actual exposure is zero. Preserve an unresolved-exposure state until reconciliation succeeds.

Sources: [research/astra-desk/src/astra_desk/broker.py:231](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/research/astra-desk/src/astra_desk/broker.py#L231); [research/astra-desk/src/astra_desk/kill_switch.py:68](https://github.com/nrsandoval1231-oss/athena-trading/blob/15fe4938241931078680cff79010ca09ce70feab/research/astra-desk/src/astra_desk/kill_switch.py#L68).

### AT-05 — P1 before trusting Astra resume: Snapshot state is not integrity-bound to the verified ledger

**Impact:** P&L, position state, weights, and the halt flag can change while the ledger still reports verified.

The store checks that snapshot head_hash and entry_count match the chain. It then trusts the snapshot's operational state without validating a digest of that state or rebuilding it from ledger events.

**Reproduction:** Created a legitimate stored paper session, persisted a halted state, then edited only snapshot.json: halted=false and realized_pnl=999999.0. Reload accepted the edited values; the unchanged chain still returned ledger_verified.

**Repair:** Bind the entire snapshot to an independently checked checkpoint or derive state by deterministic replay. Verify strategy/contract identity as part of restore. Add corruption tests for P&L, positions, halt state, and weights, not just chain edits.

## The product milestone that matters

**The current Ollama runner does not yet test Athena learning.** This is a disclosed implementation limitation, not a newly discovered unauthorized claim.

_opportunity_packet always builds a D_ATHENA-compatible packet with memory=(). The B/C/D calls use the same prompt and packet; the non-deliberation payload builder does not vary their treatment. Their labels differ in the ledger, but their request hashes are identical. The result explicitly reports v2_lessons_bound=false.

An offline probe captured B_MEMORYLESS, C_NAIVE_MEMORY, and D_ATHENA and found:

- Three labeled arms, one unique request hash.
- Zero memory items in all three.
- No promoted V2 lesson inventory bound to the run.

More GPU calls cannot resolve that missing comparison. This runner can collect candidate behavior and test transport/schema acceptance, but it cannot attribute a difference between B, C, and D to learning. The main V2 runner also does not emit an end-to-end outcome comparison proving a strategy improvement.

## Recommended execution order

1. **Repair evidence integrity and the repository gate.** Close AT-01, AT-02, and AT-06. Reconcile current status. Do this before treating longer candidate runs as trustworthy evidence.
2. **Complete one small learning experiment end to end.** Produce verified opportunities, decisions, deterministic outcomes, baseline comparisons, a genuine lesson inventory, and distinct registered arm treatments. Score on a later training segment after the lesson is frozen to demonstrate the loop; label it exploratory in-sample evidence.
3. **Verify useful behavior before expanding providers or call volume.** Report per-arm action counts, accepted/rejected responses, net R after execution assumptions, drawdown, and paired differences. Keep candidate model identities separate; no pooling into a Terra claim.
4. **Finish one canonical paper execution path.** Close AT-03 and AT-07; either repair Astra's AT-04/05 before integration or keep it explicitly isolated. Demonstrate entries, partial fills, stops, exits, day-end flattening, restart, and broker reconciliation.
5. **Only then advance to a fresh, authorized held-out evaluation.** Do not reuse the consumed V1 holdout. Confirm V2 sufficiency before consuming it and preserve the registered protocol/owner authority boundaries.

**Next highest-value milestone:** a reproducible, corruption-resistant comparison that answers, “Does a specific learned lesson improve decisions versus the frozen ORB-M baseline and a memoryless Actor?” Keep live trading disabled.

No meaningful overall percentage complete is supported: engine implementation, experimental validity, and operational trading readiness have different completion criteria.

## Limits of this audit

This audit verified repository files, current GitHub status, local tests, and targeted offline behavior. It did not verify external frozen dataset contents, a live GPU/provider deployment, broker account state, a running scheduler, or a real-money/paper performance record. No profitable or general adaptation claim is supported by the evidence inspected. The listed counterexamples are reproducible implementation findings, not a claim that prior stored runs were actually altered.
